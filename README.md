# Сквозной билет

Архитектурный проект микросервисной системы для покупки единого маршрута из двух сегментов: поезда и парома. Сегменты обслуживают независимые перевозчики, а оплату выполняет отдельный платёжный провайдер.

Система должна либо успешно оформить обе брони и списать полную стоимость маршрута, либо отменить созданные брони и вернуть списанные деньги. Процесс может завершиться частично, поэтому Booking координирует последовательную saga и запускает компенсации при сбоях.

## Архитектура

Система состоит из трёх сервисов:

- **Booking** хранит заказ и управляет шагами покупки;
- **Reservations** бронирует и отменяет места у перевозчиков;
- **Payments** списывает и возвращает деньги.

Сервисы имеют отдельные базы данных и обмениваются командами и событиями через RabbitMQ. Для защиты от потери и повторной обработки сообщений используются transactional outbox, inbox и идемпотентные идентификаторы операций.

## Артефакты задания

В каталоге `docs/` находятся пять требуемых архитектурных артефактов:

1. [Карта контекстов](docs/01-context-map.md) — сервисы, их ответственность, данные и связи.
2. [C4-диаграмма уровня Container](docs/02-containers.md) — сервисы, базы данных, брокер и внешние системы.
3. [Контракты](docs/03-contracts/README.md) — OpenAPI для HTTP-вызовов и AsyncAPI для сообщений.
4. [Главный процесс](docs/04-main-process.md) — успешный сценарий и три сценария сбоя с компенсациями.
5. [Архитектурные решения](docs/05-decisions.md) — четыре ADR с контекстом, вариантами, решениями и последствиями.

Диаграммы хранятся в виде кода Mermaid, чтобы их можно было обновлять вместе с архитектурой.
