# Сквозной билет — учебный проект

Система покупает маршрут «поезд + паром» у двух независимых перевозчиков. Если весь маршрут купить не получилось, сделанные брони отменяются, а списанная сумма возвращается.

## Как объяснить проект за минуту

> У меня сервис покупки единого маршрута из поезда и парома. Booking хранит заказ и управляет покупкой. Reservations бронирует места у перевозчиков. Payments списывает и возвращает деньги. Сначала бронируем поезд, затем паром, потом оплачиваем. Если шаг не получился, отменяем предыдущие действия. Такой процесс называется saga. Сервисы обмениваются сообщениями через RabbitMQ и имеют свои базы. Повторное сообщение не должно повторно списать деньги, поэтому каждая операция имеет постоянный идентификатор.

Основной процесс: **забронировать поезд → забронировать паром → оплатить → выдать маршрут**.

## Что нужно понимать для защиты

| Вопрос | Короткий ответ |
|---|---|
| Почему нельзя просто одну транзакцию? | Базы перевозчиков и платёжного провайдера нам не принадлежат. Наша SQL-транзакция не откатит их действия. |
| Почему именно три сервиса? | У каждого своя ответственность: заказ, места, деньги. Каждый меняет только свои данные. |
| Что такое saga? | Последовательность шагов с отменой уже выполненных действий при сбое. |
| Что такое компенсация? | Отдельное обратное действие: отменить бронь или вернуть деньги. |
| Что такое идемпотентность? | Повтор запроса с тем же идентификатором возвращает прежний результат без второго списания или брони. |
| Зачем брокер? | Он хранит сообщения до обработки и позволяет сервисам работать независимо. |
| Зачем outbox? | Заказ и сообщение сохраняются одной транзакцией; сообщение можно отправить после перезапуска. |
| Что делать, если банк не ответил? | Сначала узнать результат по прежнему ID. Отсутствие ответа ещё не означает отказ. |

## Объём второй части

Три сервиса, один RabbitMQ и один PostgreSQL с отдельной базой для каждого сервиса. Внешние системы заменяются простыми HTTP-симуляторами с собственными хранилищами: два экземпляра перевозчика и один платёжный провайдер. Один и тот же код симулятора перевозчика можно запустить дважды.

Для демонстрации достаточно заранее заданных маршрутов, одного тестового пассажира и условных денег. Регистрация, реальные банковские интеграции, поиск маршрутов, Kubernetes и кластеры не входят в учебную версию.
